## Storage: MinIO (dev) + Cloudflare R2 (prod)

**Why they're interchangeable**: R2 is S3-compatible. MinIO is also S3-compatible. You write one storage client using the AWS SDK (`@aws-sdk/client-s3`) and swap credentials via environment variables — zero code changes between environments.

**MinIO for development**:
- Run it with Docker: one container, one command, done
- It gives you a local S3-compatible bucket with a web UI at port 9001
- You set `STORAGE_ENDPOINT`, `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`, `STORAGE_BUCKET` in your `.env`
- The SDK points to `http://localhost:9000` as the endpoint

**Cloudflare R2 for production**:
- Same env vars, different values — R2 gives you an S3-compatible endpoint like `https://<account-id>.r2.cloudflarestorage.com`
- R2 has no egress fees, which matters when workers are downloading files to process them
- You set `STORAGE_REGION=auto` (R2 doesn't use AWS regions)

**The storage service** (`services/storage.service.ts`) wraps the S3 client and exposes three methods: `upload(key, buffer, mimeType)`, `download(key)`, `delete(key)`. Everything else in the codebase calls this service — nothing touches the S3 client directly.

## How the Upload Route Syncs with Storage + Queue

The upload route is the **only place** where storage and queue meet. The flow is strictly sequential:

1. Request comes in with the file (multipart via `multer` or similar)
2. Route calls `StorageService.upload()` → gets back a `storageKey`
3. Route calls `db.evidence.create()` with `status: PENDING`, `storageKey`, `mimeType`, `fileName`, `fileSize`
4. Route calls `EvidenceQueueService.enqueueEvidenceUpload()` with the `evidenceId` and `storageKey`
5. Route responds `202 Accepted` with the `evidenceId` — the client polls for status

If step 2 fails → respond with error, nothing written to DB or queue.
If step 3 fails → you have an orphaned file in storage (handle with a cleanup job later).
If step 4 fails → you have a DB record stuck at `PENDING` forever (the maintenance queue's `CLEANUP_JOBS` handles this).

The route never waits for processing to finish. It fires and returns.

---

## How Workers Interact with Storage

Workers are the **consumers** of storage, not producers. When a processor runs:

- `IngestionProcessor.handleUpload` — just updates DB status, enqueues classification. No storage access.
- `IngestionProcessor.handleClassification` — reads `mimeType` from payload, classifies, dispatches to processing queue. No storage access.
- `PDFProcessor` (processing queue) — calls `StorageService.download(storageKey)` to get the raw file, extracts text, calls `StorageService.upload(normalizedTextKey, text)` to store the output, then enqueues the graph job with the `normalizedTextKey`.
- `ExtractionProcessor` (graph queue) — downloads the normalized text, runs LLM, stores extraction result JSON back to storage, enqueues graph update with `extractionResultKey`.

This is why payloads only carry keys — each stage downloads what it needs, does its work, uploads the output, and passes the new key downstream.

```typescript
// services/storage.service.ts
import { S3Client, PutObjectCommand, GetObjectCommand, DeleteObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const s3 = new S3Client({
    endpoint: process.env.STORAGE_ENDPOINT,       // http://localhost:9000 (minio) or https://<id>.r2.cloudflarestorage.com
    region: process.env.STORAGE_REGION || "auto",
    credentials: {
        accessKeyId: process.env.STORAGE_ACCESS_KEY!,
        secretAccessKey: process.env.STORAGE_SECRET_KEY!,
    },
    forcePathStyle: true, // required for MinIO, harmless for R2
});

const BUCKET = process.env.STORAGE_BUCKET!;

export class StorageService {
    static async upload(key: string, body: Buffer, mimeType: string) {
        await s3.send(new PutObjectCommand({ Bucket: BUCKET, Key: key, Body: body, ContentType: mimeType }));
        return key;
    }

    static async download(key: string): Promise<Buffer> {
        const res = await s3.send(new GetObjectCommand({ Bucket: BUCKET, Key: key }));
        return Buffer.from(await res.Body!.transformToByteArray());
    }

    static async delete(key: string) {
        await s3.send(new DeleteObjectCommand({ Bucket: BUCKET, Key: key }));
    }

    static async getPresignedUrl(key: string, expiresIn = 3600) {
        return getSignedUrl(s3, new GetObjectCommand({ Bucket: BUCKET, Key: key }), { expiresIn });
    }
}
```

## Step 2 — Evidence Upload Route + Controller

This is the only place where storage + DB + queue all meet. The route receives the file, saves it, creates the DB record, enqueues the job.

You need `multer` for multipart parsing. The storage key format should be deterministic: `cases/<caseId>/evidence/<uuid>.<ext>`.

```typescript
// controllers/evidence.controller.ts
import { type RequestHandler } from "express";
import { v4 as uuid } from "uuid";
import { StorageService } from "../services/storage.service";
import { EvidenceQueueService } from "../services/evidence.queue.service";
import db from "../lib/db";

export const uploadEvidence: RequestHandler = async (req, res) => {
    const file = req.file;                    // set by multer
    const { caseId } = req.params;
    const userId = req.userId!;

    if (!file) return res.status(400).json({ message: "No file provided" });

    const ext = file.originalname.split(".").pop();
    const storageKey = `cases/${caseId}/evidence/${uuid()}.${ext}`;

    // 1. Upload to storage
    await StorageService.upload(storageKey, file.buffer, file.mimetype);

    // 2. Create DB record
    const evidence = await db.evidence.create({
        data: {
            caseId,
            fileName: file.originalname,
            mimeType: file.mimetype,
            storageKey,
            fileUrl: storageKey,   // or a presigned URL if you want
            status: "PENDING",
        },
    });

    // 3. Enqueue
    await EvidenceQueueService.enqueueEvidenceUpload({
        evidenceId: evidence.id,
        caseId,
        storageKey,
        mimeType: file.mimetype,
        fileName: file.originalname,
        fileSize: file.size,
        uploadedBy: userId,
        processorVersion: "1.0",
    });

    res.status(202).json({ evidenceId: evidence.id, status: "PENDING" });
};

export const getEvidenceStatus: RequestHandler = async (req, res) => {
    const { id } = req.params;
    const evidence = await db.evidence.findUnique({ where: { id } });
    if (!evidence) return res.status(404).json({ message: "Not found" });
    res.json({ id: evidence.id, status: evidence.status });
};

export const getEvidenceByCase: RequestHandler = async (req, res) => {
    const { caseId } = req.params;
    const evidence = await db.evidence.findMany({ where: { caseId } });
    res.json({ evidence });
};
```

// queues/processors/processing/pdf.processor.ts
import type { Job } from "bullmq";
import pdfParse from "pdf-parse";
import { StorageService } from "../../../services/storage.service";
import { graphQueue } from "../../definitions/graph.queue";
import { JOB_NAMES, JOB_PRIORITY, type ProcessEvidencePayload } from "../../jobs/types";

export class PdfProcessor {
    static async handle(job: Job<ProcessEvidencePayload>) {
        const { evidenceId, caseId, storageKey } = job.data;

        await job.updateProgress(10);
        const buffer = await StorageService.download(storageKey);

        await job.updateProgress(40);
        const { text } = await pdfParse(buffer);

        const normalizedTextKey = `cases/${caseId}/normalized/${evidenceId}.txt`;
        await StorageService.upload(normalizedTextKey, Buffer.from(text), "text/plain");

        await job.updateProgress(80);
        await graphQueue.add(JOB_NAMES.EXTRACT_ENTITIES, {
            evidenceId, caseId, normalizedTextKey, processorVersion: "1.0",
        }, { priority: JOB_PRIORITY.ENTITY_EXTRACTION });

        await job.updateProgress(100);
        return { evidenceId, normalizedTextKey };
    }
}

import { v4 as uuid } from "uuid";
import { StorageService } from "../services/storage.service";
import { EvidenceQueueService } from "../services/evidence.queue.service";
import db from "../lib/db";

export const uploadEvidence: RequestHandler = async (req, res) => {
    const file = req.file;
    const { caseId } = req.params;
    const userId = req.userId!;

    if (!file) return res.status(400).json({ message: "No file provided" });

    const ext = file.originalname.split(".").pop();
    const storageKey = `cases/${caseId}/evidence/${uuid()}.${ext}`;

    // 1. Upload to storage first
    await StorageService.upload(storageKey, file.buffer, file.mimetype);

    // 2. Create DB record with PENDING status
    const evidence = await db.evidence.create({
        data: {
            caseId,
            fileName: file.originalname,
            mimeType: file.mimetype,
            storageKey,
            fileUrl: storageKey,
            status: "PENDING",
        },
    });

    // 3. Enqueue — evidenceId now exists in DB
    await EvidenceQueueService.enqueueEvidenceUpload({
        evidenceId: evidence.id,
        caseId,
        storageKey,
        mimeType: file.mimetype,
        fileName: file.originalname,
        fileSize: file.size,
        uploadedBy: userId,
        processorVersion: "1.0",
    });

    // 4. Return immediately — processing is async
    res.status(202).json({ evidenceId: evidence.id, status: "PENDING" });
};

    static async handle(job: Job<UpdateGraphPayload>) {
        const { evidenceId, caseId, extractionResultKey } = job.data;

        await job.updateProgress(10);
        const buffer = await StorageService.download(extractionResultKey);

        await job.updateProgress(30);

        // Write entities
        for (const entity of entities) {
            await session.run(
                `MERGE (e:Entity {id: $id})
                 SET e += $props, e.caseId = $caseId`,
                { id: entity.id, props: { name: entity.name, type: entity.type }, caseId }
            );
        }

        await job.updateProgress(60);

        // Write relationships
        for (const rel of relationships) {
            await session.run(
                `MATCH (a:Entity {id: $fromId}), (b:Entity {id: $toId})
                 MERGE (a)-[r:RELATES {type: $type}]->(b)
                 SET r.confidence = $confidence, r.caseId = $caseId`,
                { fromId: rel.fromId, toId: rel.toId, type: rel.type, confidence: rel.confidence, caseId }

## The Core Concept — LCEL (LangChain Expression Language)

Langchain uses a pipe syntax to chain steps:

```
prompt | model | outputParser
```

Each piece is swappable. You can swap `ChatOpenAI` for `ChatAnthropic` or `ChatGoogleGenerativeAI` without touching the prompt or parser.

---

## How It Maps to Your Extraction Processor

**1. The model** — instead of `new OpenAI()`, you use `new ChatOpenAI()` from `@langchain/openai`. This gives you `.withStructuredOutput()` which is the key method.

**2. Structured output with Zod** — instead of `JSON.parse()` on a raw string, you define a Zod schema for what you expect back. Langchain handles the prompt injection and parsing automatically. If the LLM returns malformed JSON, Langchain retries internally.

```typescript
import { z } from "zod";

const ExtractionSchema = z.object({
    entities: z.array(z.object({
        id: z.string(),
        type: z.enum(["Person", "Organization", "Location", "Object", "Concept"]),
        name: z.string(),
        aliases: z.array(z.string()),
    })),
    relationships: z.array(z.object({
        fromId: z.string(),
        toId: z.string(),
        type: z.string(),
        confidence: z.number(),
    })),
    events: z.array(z.object({
        title: z.string(),
        description: z.string(),
        occurredAt: z.string().nullable(),
        confidence: z.number(),
    })),
});
```

**3. The chain** — you build it once outside the class, then call `.invoke()` per job:

```typescript
import { ChatOpenAI } from "@langchain/openai";
import { ChatPromptTemplate } from "@langchain/core/prompts";

const model = new ChatOpenAI({ model: "gpt-4o-mini" });

const prompt = ChatPromptTemplate.fromMessages([
    ["system", "Extract entities, relationships, and events from the evidence text. Be precise and only extract what is explicitly stated."],
    ["human", "{text}"],
]);

const chain = prompt.pipe(model.withStructuredOutput(ExtractionSchema));

// In the processor:
const extraction = await chain.invoke({ text });
// extraction is fully typed — extraction.entities, extraction.relationships, extraction.events
// No JSON.parse(), no try/catch around parsing
```

---

## The Big Wins Over Raw OpenAI SDK

- `withStructuredOutput()` gives you a fully typed return value — `extraction.entities` is `Entity[]`, not `any`
- Zod validation runs automatically — if the LLM hallucinates a field, it throws a typed error instead of silently passing bad data downstream
- Swapping models is one line — change `ChatOpenAI` to `ChatAnthropic`, the rest of the chain stays identical
- Langchain has built-in retry logic for structured output failures
- You can add `.withFallbacks([cheaperModel])` so if `gpt-4o` fails it falls back to `gpt-4o-mini` automatically

## One Thing to Watch

`withStructuredOutput()` uses either function calling or JSON mode under the hood depending on the model. For OpenAI models it uses function calling which is more reliable than `response_format: json_object`. This means the Zod schema directly controls what the model is instructed to return — it's not just validation after the fact, it shapes the prompt itself.

So the flow becomes:

```
normalized text
    ↓
ChatPromptTemplate injects it into the system/human messages
    ↓
ChatOpenAI with withStructuredOutput(ExtractionSchema) calls the model
    ↓
Langchain validates + parses the response against the Zod schema
    ↓
You get a fully typed ExtractionSchema output — no manual parsing at all
    ↓
StorageService.upload(resultKey, JSON.stringify(extraction))
    ↓
graphQueue.add(UPDATE_GRAPH, { extractionResultKey })
```

That's the entire integration — the rest of the processor (storage download, storage upload, queue dispatch) stays exactly the same.

## Extraction Processor — with LangChain

The docs confirm that `withStructuredOutput()` with a Zod schema is the preferred approach. It uses function calling under the hood (not JSON mode), which means the schema directly shapes what the model is instructed to return — not just validation after the fact.

### `queues/processors/extraction.processor.ts`

```typescript
import type { Job } from "bullmq";
import { z } from "zod";
import { ChatOpenAI } from "@langchain/openai";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { StorageService } from "../../services/storage.service";
import { graphQueue } from "../definitions/graph.queue";
import { JOB_NAMES, JOB_PRIORITY, type ExtractEntitiesPayload } from "../jobs/types";

// Zod schema — validated automatically, fully typed return value
const ExtractionSchema = z.object({
    entities: z.array(z.object({
        id: z.string().describe("A unique identifier for this entity"),
        type: z.enum(["Person", "Organization", "Location", "Object", "Concept"]),
        name: z.string(),
        aliases: z.array(z.string()),
    })),
    relationships: z.array(z.object({
        fromId: z.string(),
        toId: z.string(),
        type: z.string().describe("e.g. WORKS_FOR, LOCATED_AT, OWNS"),
        confidence: z.number().min(0).max(1),
    })),
    events: z.array(z.object({
        title: z.string(),
        description: z.string(),
        occurredAt: z.string().nullable().describe("ISO8601 date string or null if unknown"),
        confidence: z.number().min(0).max(1),
    })),
});

// Build chain once at module level — not inside the handler
const model = new ChatOpenAI({ model: "gpt-4o-mini", temperature: 0 });

const prompt = ChatPromptTemplate.fromMessages([
    ["system", "You are a forensic analyst. Extract all entities, relationships, and events from the evidence text. Only extract what is explicitly stated — do not infer."],
    ["human", "{text}"],
]);

// prompt | model.withStructuredOutput() — this is the LCEL pipe pattern from the docs
const extractionChain = prompt.pipe(model.withStructuredOutput(ExtractionSchema));

export class ExtractionProcessor {
    static async handle(job: Job<ExtractEntitiesPayload>) {
        const { evidenceId, caseId, normalizedTextKey } = job.data;

        await job.updateProgress(10);
        const buffer = await StorageService.download(normalizedTextKey);
        const text = buffer.toString("utf-8");

        await job.updateProgress(30);

        // Returns fully typed ExtractionSchema output — no JSON.parse(), no try/catch around parsing
        const extraction = await extractionChain.invoke({ text });

        await job.updateProgress(70);

        const resultKey = `cases/${caseId}/extractions/${evidenceId}.json`;
        await StorageService.upload(
            resultKey,
            Buffer.from(JSON.stringify(extraction)),
            "application/json"
        );

        await graphQueue.add(JOB_NAMES.UPDATE_GRAPH, {
            evidenceId,
            caseId,
            extractionResultKey: resultKey,
            processorVersion: "1.0",
        }, { priority: JOB_PRIORITY.GRAPH_UPDATE });

        await job.updateProgress(100);
        return { evidenceId, resultKey, entityCount: extraction.entities.length };
    }
}
```

Key things from the docs:
- `withStructuredOutput(ZodSchema)` is the preferred method per the docs — Zod schemas provide automatic validation, JSON Schema requires manual validation
- `temperature: 0` on the model for deterministic extraction
- The chain is built once at module level, not inside the handler — avoids re-instantiating on every job

## Embedding Processor — with LangChain

The docs show two things that replace the raw OpenAI embeddings API:
- `OpenAIEmbeddings` from `@langchain/openai` with `embedDocuments(chunks)` for batch embedding
- `RecursiveCharacterTextSplitter` from `@langchain/textsplitters` for chunking — the docs explicitly call this "the recommended TextSplitter for generic text use cases"
- `QdrantVectorStore` from `@langchain/qdrant` which wraps the Qdrant client and handles `addDocuments()` directly

### `queues/processors/embedding.processor.ts`

```typescript
import type { Job } from "bullmq";
import { OpenAIEmbeddings } from "@langchain/openai";
import { QdrantVectorStore } from "@langchain/qdrant";
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";
import { Document } from "@langchain/core/documents";
import { StorageService } from "../../services/storage.service";
import { reasoningQueue } from "../definitions/reasoning.queue";
import { JOB_NAMES, JOB_PRIORITY, type GenerateEmbeddingsPayload } from "../jobs/types";

// All three built once at module level
const embeddings = new OpenAIEmbeddings({
    model: "text-embedding-3-small",
    apiKey: process.env.OPENAI_API_KEY,
});

// QdrantVectorStore.fromExistingCollection — exact pattern from the docs
const getVectorStore = () => QdrantVectorStore.fromExistingCollection(embeddings, {
    url: process.env.QDRANT_URL,
    collectionName: process.env.QDRANT_COLLECTION!,
});

// RecursiveCharacterTextSplitter — recommended by docs for generic text
const splitter = new RecursiveCharacterTextSplitter({
    chunkSize: 1000,
    chunkOverlap: 200,
});

export class EmbeddingProcessor {
    static async handle(job: Job<GenerateEmbeddingsPayload>) {
        const { evidenceId, caseId, chunkKeys } = job.data;

        await job.updateProgress(10);

        // Download all normalized text files for this evidence
        const rawTexts: string[] = [];
        for (const key of chunkKeys) {
            const buffer = await StorageService.download(key);
            rawTexts.push(buffer.toString("utf-8"));
        }

        await job.updateProgress(30);

        // splitDocuments — from the docs, this is the correct method for Document objects
        const docs = rawTexts.map(text => new Document({
            pageContent: text,
            metadata: { evidenceId, caseId },
        }));

        const splits = await splitter.splitDocuments(docs);

        await job.updateProgress(50);

        // addDocuments handles embedding + upsert in one call
        const vectorStore = await getVectorStore();
        await vectorStore.addDocuments(splits);

        await job.updateProgress(80);

        // Trigger hypothesis update
        await reasoningQueue.add(JOB_NAMES.UPDATE_HYPOTHESES, {
            caseId,
            triggerReason: "new-evidence",
            newEvidenceCount: 1,
        }, { priority: JOB_PRIORITY.HYPOTHESES });

        await job.updateProgress(100);
        return { evidenceId, chunkCount: splits.length };
    }
}
```

Key things from the docs:
- `embedDocuments(string[])` is the batch embedding method per the docs — more efficient than calling one at a time
- `QdrantVectorStore.fromExistingCollection(embeddings, { url, collectionName })` — exact signature from the docs
- `addDocuments(splits)` handles both embedding and upsert in one call — no manual point construction needed
- `RecursiveCharacterTextSplitter` with `chunkSize: 1000, chunkOverlap: 200` — the exact values the docs use in their RAG examples

## Reasoning Processor — with LangChain

The hypothesis update processor uses `similaritySearch` to pull relevant evidence chunks from Qdrant, then feeds them to the LLM to update hypotheses. This is the RAG pattern the docs describe.

### `queues/processors/reasoning.processor.ts`

```typescript
import type { Job } from "bullmq";
import { z } from "zod";
import { ChatOpenAI } from "@langchain/openai";
import { OpenAIEmbeddings } from "@langchain/openai";
import { QdrantVectorStore } from "@langchain/qdrant";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { UpdateHypothesesPayload } from "../jobs/types";
import db from "../../lib/db";

const HypothesisSchema = z.object({
    hypotheses: z.array(z.object({
        content: z.string().describe("The hypothesis statement"),
        confidence: z.number().min(0).max(1),
        supportingEvidenceIds: z.array(z.string()),
    })),
});

const model = new ChatOpenAI({ model: "gpt-4o-mini", temperature: 0 });
const embeddings = new OpenAIEmbeddings({ model: "text-embedding-3-small" });

const hypothesisChain = ChatPromptTemplate.fromMessages([
    ["system", "You are a forensic analyst. Based on the evidence below, generate or update hypotheses about what happened. Be precise and evidence-based."],
    ["human", "Evidence:\n{evidence}\n\nExisting hypotheses:\n{existing}\n\nGenerate updated hypotheses."],
]).pipe(model.withStructuredOutput(HypothesisSchema));

export class ReasoningProcessor {
    static async handleHypothesisUpdate(job: Job<UpdateHypothesesPayload>) {
        const { caseId } = job.data;

        await job.updateProgress(10);

        // Pull relevant evidence from Qdrant using similaritySearch
        const vectorStore = await QdrantVectorStore.fromExistingCollection(embeddings, {
            url: process.env.QDRANT_URL,
            collectionName: process.env.QDRANT_COLLECTION!,
        });

        // similaritySearch — exact method from the docs
        const relevantChunks = await vectorStore.similaritySearch(
            `case ${caseId} evidence summary`,
            10  // top 10 most relevant chunks
        );

        await job.updateProgress(30);

        const existingHypotheses = await db.hypothesis.findMany({ where: { caseId } });

        const evidence = relevantChunks.map(c => c.pageContent).join("\n\n---\n\n");
        const existing = existingHypotheses.map(h => h.content).join("\n") || "None yet";

        await job.updateProgress(50);

        const result = await hypothesisChain.invoke({ evidence, existing });

        await job.updateProgress(80);

        // Upsert hypotheses into Postgres
        for (const h of result.hypotheses) {
            await db.hypothesis.create({
                data: {
                    caseId,
                    content: h.content,
                    confidence: h.confidence,
                    status: "ACTIVE",
                },
            });
        }

        await job.updateProgress(100);
        return { caseId, hypothesisCount: result.hypotheses.length };
    }
}
```

| | Raw OpenAI SDK | LangChain |
|---|---|---|

```typescript
